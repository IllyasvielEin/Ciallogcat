# UI 设计与性能

## 操作与布局

界面按设备选择、采集控制、日志筛选、日志阅读组织操作。设计依据为桌面鼠标与键盘操作习惯；可用性评估不包含用户访谈或用户实验。

| 区域 | 行为 | 设计目的 |
| --- | --- | --- |
| 两层工具栏 | 第一行放设备、采集、缓冲区、View、File、预设及跟随；第二行放包名、消息、Tag 与六个级别按钮，每行 44 逻辑像素 | 保留主要操作直达，同时增加日志阅读空间 |
| 关键词 | `.*` 和 `Aa` 位于输入框右侧，并提供提示 | 筛选条件就近设置 |
| Tag | 菜单分别设置包含和排除；有条件时标记 `Tag •` | 用两个明确条件处理常见噪声，无需引入查询语言 |
| View 菜单 | 包含主题、行高、详情开关及日志内存预算 | 为常用筛选控件保留空间 |
| File 菜单 | 打开 v1/v2、另存保留日志、导出当前筛选、关闭文件 | 后台处理文件并保留来源与范围 |
| 级别按钮 | 点击区域至少 28×28 逻辑像素，提示完整级别与“及以上”语义 | 便于定位，并结合文字与颜色表达级别 |
| 详情区 | 选中日志时展开，取消选择时收起；展开后保持所选行可见 | 兼顾日志列表与完整消息阅读 |
| 空状态 | 区分未找到 ADB、未选设备、等待日志、无匹配与筛选错误 | 提示可执行的下一步操作 |
| 键盘操作 | Ctrl+F 或 `/` 查找；方向键、Home/End 选择；Ctrl+End 跟随；Ctrl+Enter 查看/退出上下文；F3 / Shift+F3 定位详情命中；Esc 退出输入、上下文或选择 | 支持连续阅读，输入时不抢占导航键 |
| 复制 | Ctrl+C 优先复制选中文字，否则复制所选日志；小请求即时完成，大请求后台准备后点击“复制已准备好”；详情 Copy 按钮复制完整日志 | 遵循文字选择习惯，避免后台完成时意外覆盖剪贴板 |
| Clear | 空列表及只读文件视图时禁用，与跟随控件分隔；只清空本地实时日志 | 减少误操作，保留设备缓冲区 |
| 窄窗口 | 进程与 Tag 列可压缩，长设备名截断显示 | 优先保留消息和主要控件空间 |

设备由用户手动选择。包名、级别、Tag 和关键词筛选在本地执行，不重启采集。界面使用中文和英文标签。状态栏显示保留总数与匹配数，内存估算在匹配数提示中，预算设置在 View 菜单中。

Tag 包含和排除各表示一个区分大小写的字面子串，空字符串表示停用，空格按字面匹配；输入内容不会按逗号或空格拆分。包含条件与其他筛选同时成立，排除条件优先拒绝命中；消息的 `.*`、`Aa` 不改变 Tag 语义。两个条件随配置、筛选预设和筛选导出的描述保存，旧配置缺省为空。

选中行的详情或右键菜单可进入上下文，固定显示该行前后最多各 50 条已保留记录，并暂时忽略所有筛选条件。采集继续，跟随暂停，键盘选择和复制作用于上下文中可见的日志；导出当前筛选仍采用原筛选条件。返回时用来源、绝对位置及已有记录身份恢复原行与原筛选视口，前缀裁剪不会把相同索引误认为原行。原行已过期时给出提示，返回当前筛选结果；修改筛选或恢复跟随会退出上下文。

详情的上一个/下一个命中按钮及 F3 / Shift+F3 使用当前已生效消息筛选的同一正则，包括字面模式和大小写语义。后台对完整消息查找，因此预览外的命中、跨显示分段的匹配和正则锚点仍保持原语义。导航最多记录前 4096 处命中，达到上限时明确标注；这个上限不截断日志内容、筛选或复制。切换选中行或条件会取消旧请求，旧结果不能覆盖新选择。

详情元数据行以可点击的 `seq #N · segment N` 显示原生记录身份，悬停可查看完整 session UUID、attempt 和主机观察时间；点击复制含 `identity_scope: capture_session`、`session_id`、`seq` 的 JSON，并取消旧后台复制。旧文件没有来源会话时只显示 `artifact-local seq`，复制当前 `artifact_id` 与文档内序号；没有身份的临时记录不补造引用。这些是可核验的记录身份，不是 CLI 的本机 HMAC 查询 token，原有整条日志复制文本保持不变。

文件入口支持路径输入与拖放；后台加载候选，验证成功后再切换。普通保存固定快照并继续采集；“保存后打开”先停止并排空，保存成功才替换。详细的只读、取消、原子发布与峰值内存边界见 [文件工作流](file-workflow.md)。这些代码行为已有自动化回归；2026-10-23 已在 WSLg X11 实际完成路径打开、筛选、详情、保存和重开，原生拖放与其他桌面环境需另验收。

采集状态区分正在停止、有限重连与停止超时。暂停或关闭会取消重连，旧流未确认退出时不能新启；即使切回原设备，也按稳定来源会话拒绝旧流数据。默认重连最多三次，退避为 1/2/4 秒，30 秒稳定运行后恢复重试预算。

日志表格在可用宽度低于 1050 逻辑像素时，将未手动调整的 PROCESS / TAG 列从 210 / 165 缩到 140 / 110；变宽后恢复默认。拖动某一列只覆盖该列，本次运行内保留该宽度，不影响另一列自适应。切换宽度不重置表格滚动位置；进行中的列拖动结束后再应用窄窗口默认值。手动设置的超宽列是显式偏好，必要时可再拖小。

启用 AccessKit 时，日志区域暴露表格、表头、可见行和六个字段单元格。总行数包含表头，行位置使用当前列表（筛选或上下文）中的序号，选中状态与列表一致；字段关联对应表头。行支持真实聚焦和激活，未选中但聚焦的行显示边框，方向键将焦点与目标选择同步。行名称也包含有界的各字段摘要，以便缺少表格接口的平台仍可朗读当前行；消息的无障碍预览与视觉预览使用相同长度上限，完整内容仍由详情和复制提供。虚拟列表只生成可见行节点；这不等同于所有系统均支持完整读屏表格导航。当前 AccessKit Unix 桥接版本尚不提供 AT-SPI Table / TableCell 接口和表头关联关系；角色、字段摘要和逐行聚焦不能替代这些接口。


## 日志存储与绘制

日志按估算内存预算滚动保留，默认 300 MiB，可调范围 16–4096 MiB；超限时裁剪到预算的 90%。预算覆盖保留的日志数据，不是进程 RSS 硬上限。索引、快照及预算的说明见 [README](../README.zh-CN.md#内存保留)。

- 日志按 1024 条分块，筛选快照共享块；追加只复制需要写入的共享块。GUI 不再使用未来 PID 快照回填未知历史记录；新记录的进程名只采用有效观察窗口内的采样提示，并显示其推定来源。
- 筛选保留一个活动请求、一个最新待处理请求和一个最新完成结果。新请求或关闭会使旧扫描在行数/字节检查点协作退出；编译与单次正则匹配不可抢占。正在退出的快照仍可能短暂持有淘汰块，旧预算快照和分配器驻留量不属于当前保留估算。
- 已扫描的快照结果立即发布。尾部补筛直接索引分块存储，每轮最多 2048 行、2 MiB 被检查估算字节或目标 2 ms，并向前推进绝对位置；这些目标不能保证最大帧时间或 GPU FPS。
- 前缀淘汰直接丢弃共享整块，仅边界部分块需要写时复制。匹配索引、选择、Shift 锚点和详情按过期前缀修正；可见缓存保留绝对行身份。浏览时恢复滚动位置，仍跟随时保持跟随。
- 同一筛选的尾部补筛期间，未检查的选中行保留并标为 checking。只有已确认排除或过期的行被移除。四个整条日志复制入口统一等待完整选择、检查准确 UTF-8 字节数并遵守 16 MiB 输出上限，不会部分复制或稍后自动复制。
- 最多 256 条且不超过 64 KiB 的复制在 UI 线程完成；更大请求固定日志快照、选择和来源版本，由单个后台工作线程准备，并在逐行检查点取消旧任务。完成后需点击“复制已准备好”，也可随时取消；新复制、来源/筛选/选择变化或保留前缀淘汰都使旧结果失效。持续追加不会把后来日志加入请求。保留一个活动请求、一个最新请求和一个结果，取消前的快照可能短暂持有已淘汰块；16 MiB 是输出上限，不是系统剪贴板或进程 RSS 上限。
- View 内的预算是草稿，Apply 才更新配置并按当前保留量裁剪；Cancel、Esc 或关闭菜单丢弃草稿。显式降低预算时回收匹配向量容量，不在每次裁剪时反复缩容。
- 后台事件队列最多积压 4096 个事件，日志另受 16 MiB 字节预算约束，满时读取线程等待。这是传输队列限制，日志保留量由内存预算决定。
- 采集端单行最多接收 1 MiB 原始字节，超过部分丢弃并标注 `truncated`。
- 每轮最多处理 2048 个事件，目标时间预算为 4 ms；单个事件不可抢占，预算不是硬实时保证。
- 日志流通过每个流一个休眠计时线程与一个待处理期限合并 16 ms 内的重绘请求；后续日志不延后该期限，静默前的最后一条也会触发唤醒。筛选、详情定位及查询结果发布后主动唤醒 UI，达到每帧事件/补筛预算时显式续帧。GUI 按筛选防抖、配置保存、设备/进程查询、进程样本到期、采集停止/重连和速率显示的期限调度，没有无条件 100 ms 泵；文件任务期间保留 50 ms 进度刷新。系统调度仍可能延迟实际唤醒，高亮正则仅在条件变化时编译。
- 日志表格采用虚拟列表。单行预览最多 2048 字节，保持 UTF-8 边界；超过 16 KiB 或带命中高亮的详情按不超过 512 字节的分段虚拟显示。命中跳转同时定位纵向分段和横向文本位置，每帧只排版可见分段。详情查找保留一个活动请求、一个最新待处理请求和一个最新结果，单次正则搜索仍不可抢占。复制与筛选使用已接收的完整消息。

## 性能测量

在 release 模式下运行合成日志测试：

```bash
cargo test --locked --release performance::measure_ui -- --ignored --nocapture
```

测试调用实际工具栏、详情区与虚拟日志表格，并执行三角化。20 万条含中文日志场景先等待后台筛选与高亮结果应用，并断言匹配成功，再测量 1280×820、900×560 的静止视口，以及移动视口、窄窗口详情。移动通过真实表格滚动偏移切换可见范围；这不包含原生滚轮事件到呈现的延迟。每场景预热 10 帧、采样 60 帧，因此输出是预热后的 CPU 数据，不代表冷启动或首字形成本。另测共享快照下的追加与裁剪、正则扫描、超长消息和突发采集。日志条数是测试输入规模，不代表产品保留上限。

输出包含 CPU 侧布局、文字处理、三角化与采集事件处理的耗时统计。测量受机器配置、运行负载和调度影响；比较结果时应记录操作系统、Rust 版本、构建模式和样本规模。测试不设置毫秒级通过阈值，也不测量 GPU 帧率或真机日志吞吐。

选择和复制另用 `cargo test --locked --release --bin ciallogcat performance::measure_selection_copy -- --ignored --nocapture` 测量。2026-10-23 在 WSL2 Linux 6.18.33.2、Core Ultra 7 270K Plus、Rust 1.97.1 release 下，每项预热 3 次、采样 12 次；下表为 p95（小样本中等于最大样本），不是帧时间保证。

| UI 线程操作 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 20 万条全选 | 0.519 ms | 0.797 ms |
| 20 万条 Shift 范围 | 6.629 ms | 0.767 ms |
| 100 万条全选 | 7.850 ms | 7.593 ms |
| 100 万条 Shift 范围 | 36.107 ms | 7.868 ms |
| 16 MiB / 10 万条复制请求 | 13.114 ms | 0.142 ms |

选择仍使用 `BTreeSet`，只将普通 Shift 大范围的逐项插入改成有序批量构造；百万选中索引冻结为后台请求的 p95 为 3.010 ms，没有引入范围索引架构。16 MiB 请求后台完成的 p95 为 12.407 ms，准备后的显式剪贴板命令 p95 为 0.001 ms；后者只把已完成字符串交给 egui，不包含操作系统剪贴板转换、分配和传输成本。

## 验证范围

自动测试覆盖日志预算裁剪、分块快照、进程采样与历史隔离、异步筛选、队列背压、异常行截断、缓冲区参数、会话隔离、配置序列化、原生复制事件和键盘导航。UI 交互测试使用 egui 输入事件；阅读增量另覆盖 900×560 两层工具栏的控件边界与重叠、Tag 输入及预设、上下文键盘/复制/裁剪返回、预览外与跨段命中、定位上限和过期结果隔离。这些 Harness 结果不替代原生 IME、系统读屏或 GPU 验收。

2026-10-11 的云端原生交互测试使用模拟 ADB 数据，范围如下：

- Xfce/X11：窗口绘制、鼠标键盘、筛选历史、滚动跟随、列宽调整、中文输入提交/取消和 Unicode 系统剪贴板通过测试。中文候选框仍错误定位到屏幕左上角；已观察到应用输出非零且随光标变化的坐标，后续 XIM 传递的根因尚未确定。
- 嵌套 Weston 的原生 Wayland 路径：绘制、导航、筛选历史及同会话 Unicode 剪贴板通过。调整宿主窗口大小时 Weston 崩溃，且缺少 text-input-v3，无法验收该路径的中文输入法。

2026-10-23 补充 WSLg X11 原生验收：900×560 文件打开/筛选/详情/上下文/保存/重开、125%/150% 强制缩放通过；上下文遮挡已修复。身份复制与 2,196,125 字节后台大复制经系统剪贴板逐字节核对，确认前不会自动覆盖。另完成 30 分钟合成 CLI 采集，版本范围与限制见[验证摘要](validation.md)。

这些结果不等同于 Ubuntu GNOME、Windows 或真实 Android 设备验收。Windows 原生窗口启动和窄窗口空状态仅经过截图检查；整窗拖动耗时、GPU 提交与呈现、真机持续吞吐、设备拔插和长时间内存走势仍未完成验证。

## 图形诊断

窗口默认请求 `AutoVsync`，最大帧延迟为 1。Windows 可通过 `CIALLOGCAT_VSYNC=0` 请求实验性的 `AutoNoVsync`；未设置或值为 `1` 时使用默认模式。驱动决定可用呈现模式，自动模式可能回退。

Windows 整窗拖动可能出现卡顿。egui-winit 在收到 `WindowEvent::Moved` 时请求重绘，wgpu 的画面获取与呈现运行在窗口线程；这些机制不足以确认卡顿根因，需要实际拖动期间的线程和 GPU 耗时数据。

非同步模式可能增加功耗或出现撕裂，且存在原生窗口捕获空白的兼容性问题，不保证改善拖动流畅度。诊断时每次只运行一个实例并保持其他条件一致：

```powershell
$env:CIALLOGCAT_VSYNC = '0'
.\target\release\ciallogcat.exe
```

使用默认同步模式：

```powershell
$env:CIALLOGCAT_VSYNC = '1'
.\target\release\ciallogcat.exe
```

启动前将 `CIALLOGCAT_GRAPHICS_REPORT` 设置为可写文件路径，可记录显卡、后端、驱动与请求的呈现参数；报告不包含日志内容。`CIALLOGCAT_VSYNC` 实验开关仅作用于 Windows。
