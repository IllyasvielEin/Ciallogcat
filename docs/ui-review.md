# UI 设计与性能

## 操作与布局

界面按设备选择、采集控制、日志筛选、日志阅读组织操作。设计依据为桌面鼠标与键盘操作习惯；可用性评估不包含用户访谈或用户实验。

| 区域 | 行为 | 设计目的 |
| --- | --- | --- |
| 采集栏 | 开启/暂停、关闭、缓冲区选择及内存占用集中显示 | 便于判断采集状态和控制会话 |
| 关键词 | `.*` 和 `Aa` 位于输入框右侧，并提供提示 | 筛选条件就近设置 |
| View 菜单 | 包含主题、行高、详情开关及日志内存预算 | 为常用筛选控件保留空间 |
| 级别按钮 | 点击区域至少 28×28 逻辑像素，提示完整级别与“及以上”语义 | 便于定位，并结合文字与颜色表达级别 |
| 详情区 | 选中日志时展开，取消选择时收起；展开后保持所选行可见 | 兼顾日志列表与完整消息阅读 |
| 空状态 | 区分未找到 ADB、未选设备、等待日志、无匹配与筛选错误 | 提示可执行的下一步操作 |
| 键盘操作 | Ctrl+F 或 `/` 查找；方向键、Home/End 选择；Ctrl+End 跟随；Esc 退出输入或取消选择 | 支持连续阅读，输入时不抢占导航键 |
| 复制 | Ctrl+C 优先复制选中文字，否则复制所选日志；详情 Copy 按钮复制完整日志 | 遵循文字选择习惯 |
| Clear | 空列表时禁用，与 Tail 分隔；只清空本地日志 | 减少误操作，保留设备缓冲区 |
| 窄窗口 | 进程与 Tag 列可压缩，长设备名截断显示 | 优先保留消息和主要控件空间 |

设备由用户手动选择。包名、级别和关键词筛选在本地执行，不重启采集。界面使用中文和英文标签。

日志表格在可用宽度低于 1050 逻辑像素时，将未手动调整的 PROCESS / TAG 列从 210 / 165 缩到 140 / 110；变宽后恢复默认。拖动某一列只覆盖该列，本次运行内保留该宽度，不影响另一列自适应。切换宽度不重置表格滚动位置；进行中的列拖动结束后再应用窄窗口默认值。手动设置的超宽列是显式偏好，必要时可再拖小。

启用 AccessKit 时，日志区域暴露表格、表头、可见行和六个字段单元格。总行数包含表头，行位置使用当前筛选结果中的序号，选中状态与列表一致；字段关联对应表头。行支持真实聚焦和激活，未选中但聚焦的行显示边框，方向键将焦点与目标选择同步。行名称也包含有界的各字段摘要，以便缺少表格接口的平台仍可朗读当前行；消息的无障碍预览与视觉预览使用相同长度上限，完整内容仍由详情和复制提供。虚拟列表只生成可见行节点；这不等同于所有系统均支持完整读屏表格导航。当前 AccessKit Unix 桥接版本尚不提供 AT-SPI Table / TableCell 接口和表头关联关系；角色、字段摘要和逐行聚焦不能替代这些接口。


## 日志存储与绘制

日志按估算内存预算滚动保留，默认 300 MiB，可调范围 16–4096 MiB；超限时裁剪到预算的 90%。预算覆盖保留的日志数据，不是进程 RSS 硬上限。索引、快照及预算的说明见 [README](../README.zh-CN.md#内存保留)。

- 日志按 1024 条分块，筛选快照共享块；追加和进程补全只复制需要写入的共享块。
- 筛选保留一个活动请求、一个最新待处理请求和一个最新完成结果。新请求或关闭会使旧扫描在行数/字节检查点协作退出；编译与单次正则匹配不可抢占。进程补全先完成裁剪，再发布包名筛选快照。正在退出的快照仍可能短暂持有淘汰块，旧预算快照和分配器驻留量不属于当前保留估算。
- 已扫描的快照结果立即发布。尾部补筛直接索引分块存储，每轮最多 2048 行、2 MiB 被检查估算字节或目标 2 ms，并向前推进绝对位置；这些目标不能保证最大帧时间或 GPU FPS。
- 前缀淘汰直接丢弃共享整块，仅边界部分块需要写时复制。匹配索引、选择、Shift 锚点和详情按过期前缀修正；可见缓存保留绝对行身份。浏览时恢复滚动位置，仍跟随时保持跟随。
- 同一筛选的进程补全或尾部补筛期间，未检查的选中行保留并标为 checking。只有已确认排除或过期的行被移除。四个整条日志复制入口统一等待完整选择、检查准确 UTF-8 字节数并遵守 16 MiB 输出上限，不会部分复制或稍后自动复制。
- View 内的预算是草稿，Apply 才更新配置并按当前保留量裁剪；Cancel、Esc 或关闭菜单丢弃草稿。显式降低预算时回收匹配向量容量，不在每次裁剪时反复缩容。
- 后台事件队列最多积压 4096 个事件，日志另受 16 MiB 字节预算约束，满时读取线程等待。这是传输队列限制，日志保留量由内存预算决定。
- 采集端单行最多接收 1 MiB 原始字节，超过部分丢弃并标注 `truncated`。
- 每轮最多处理 2048 个事件，目标时间预算为 4 ms；单个事件不可抢占，预算不是硬实时保证。
- 日志流合并重绘请求，筛选完成主动唤醒 UI；高亮正则仅在条件变化时编译。
- 日志表格采用虚拟列表。单行预览最多 2048 字节，保持 UTF-8 边界；超过 16 KiB 的详情按不超过 512 字节的分段虚拟显示。复制与筛选使用已接收的完整消息。

## 性能测量

在 release 模式下运行合成日志测试：

```bash
cargo test --locked --release performance::measure_ui -- --ignored --nocapture
```

测试调用实际工具栏、详情区与虚拟日志表格，并执行三角化。场景包括 1280/900 逻辑像素宽窗口、20 万条含中文日志、共享快照下的追加与裁剪、正则扫描、超长消息和突发采集。日志条数是测试输入规模，不代表产品保留上限。

输出包含 CPU 侧布局、文字处理、三角化与采集事件处理的耗时统计。测量受机器配置、运行负载和调度影响；比较结果时应记录操作系统、Rust 版本、构建模式和样本规模。测试不设置毫秒级通过阈值，也不测量 GPU 帧率或真机日志吞吐。

## 验证范围

自动测试覆盖日志预算裁剪、分块快照、进程补全、异步筛选、队列背压、异常行截断、缓冲区参数、会话隔离、配置序列化、原生复制事件和键盘导航。UI 交互测试使用 egui 输入事件。

2026-10-11 的云端原生交互测试使用模拟 ADB 数据，范围如下：

- Xfce/X11：窗口绘制、鼠标键盘、筛选历史、滚动跟随、列宽调整、中文输入提交/取消和 Unicode 系统剪贴板通过测试。中文候选框仍错误定位到屏幕左上角；已观察到应用输出非零且随光标变化的坐标，后续 XIM 传递的根因尚未确定。
- 嵌套 Weston 的原生 Wayland 路径：绘制、导航、筛选历史及同会话 Unicode 剪贴板通过。调整宿主窗口大小时 Weston 崩溃，且缺少 text-input-v3，无法验收该路径的中文输入法。

这些结果不等同于 Ubuntu GNOME、Windows 或真实 Android 设备验收。Windows 原生窗口启动和窄窗口空状态仅经过截图检查；整窗拖动耗时、GPU 提交与呈现、真机持续吞吐、设备拔插和长时间内存走势仍未完成验证。

## 图形诊断

窗口默认请求 `AutoVsync`，最大帧延迟为 1。Windows 可通过 `CIALLOGCAT_VSYNC=0` 请求实验性的 `AutoNoVsync`；未设置或值为 `1` 时使用默认模式。驱动决定可用呈现模式，自动模式可能回退。

Windows 整窗拖动可能出现卡顿。egui-winit 在收到 `WindowEvent::Moved` 时请求重绘，wgpu 的画面获取与呈现运行在窗口线程；这些机制不足以确认卡顿根因，需要实际拖动期间的线程和 GPU 耗时数据。

非同步模式可能增加功耗或出现撕裂，且存在原生窗口捕获空白的兼容性问题，不保证改善拖动流畅度。诊断时每次只运行一个实例并保持其他条件一致：

```powershell
$env:CIALLOGCAT_VSYNC = '0'
.\target\release\ciallogcat.exe
```

使用默认同步模式：

```powershell
$env:CIALLOGCAT_VSYNC = '1'
.\target\release\ciallogcat.exe
```

启动前将 `CIALLOGCAT_GRAPHICS_REPORT` 设置为可写文件路径，可记录显卡、后端、驱动与请求的呈现参数；报告不包含日志内容。`CIALLOGCAT_VSYNC` 实验开关仅作用于 Windows。
