# 项目目标与架构方向

目标是可靠、易读的 GUI Logcat 获取与查看工具，同时通过 headless CLI 为 Agent 提供有边界、可引用的日志证据。优先关键路径、共享契约和可解释行为；设备安装、点击及测试编排由已有执行器负责。

## 当前实现

- 共享 Rust 核心承担 ADB 生命周期、记录、筛选、文档格式、预算及诊断；GUI 与 CLI 复用这些语义，见 [核心接口](headless-core.md)。
- 采集控制器分离用户意图与进程状态，支持有界重连、停止排空和回收。稳定 session/seq 身份贯穿清空、裁剪、重连与导出；未知丢失量不伪造。
- 共用历史范围支持最近 N 条、since、有限 dump 和 buffers；主机快照预算、GUI 留存预算及查询预算分别表达。历史记录不套用当前 ps 身份；默认实时 ps 仍只是未验证提示。
- GUI 区分浏览跟随与采集，提供完整消息、F3 定位、独立上下文、F8 崩溃/ANR 线索、引用复制和后台文件操作。打开失败保留旧视图，保存/导出冻结来源和筛选条件，见 [文件工作流](file-workflow.md)。
- 原生 v2/v3 保留身份、来源、采集事实和扩展；v3 proto 仅存原始 payload，固定投影恢复展示，兼容 v2 导出。未知 JSON 数值保真、转换取消和资源预算有回归。见 [格式契约](native-format.md)。
- Agent 查询有响应/扫描预算、snapshot/tail cursor、全文 stored/decoded 和上下文。示例先取得已发布尾部起点，再围绕外部动作返回有限证据，见 [查询契约](agent-query.md) 与 [测试工作流](agent-test-workflow.md)。
- 只读设备诊断按需执行，独立保留失败、截断和观察时间；不修改设备 logd 配置，见 [诊断契约](device-diagnostics.md)。

## 保持的取舍

默认策略不因合成基准切换；proto/v3 显式选择且失败不静默降级。v3 节省磁盘并不保证吞吐更高，见 [性能对照](transport-performance-2026-10-24.md)。

GUI 留存预算不是进程 RSS 硬上限；离线导入不静默截尾。文件发布要求目标文件系统支持当前原子发布机制。普通文本复制不能代替包含身份和来源的证据工件。原始 protobuf 也不是原始 logd 字节。
