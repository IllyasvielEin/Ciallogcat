# Ciallogcat v1.3.0

## Breaking changes — CLI, archives and sessions

This release deliberately removes backward-compatibility paths. It updates both the desktop application and the headless CLI. Keep an older executable alongside older archives if they must remain readable; this release does not convert or delete them. Finish active sessions with the version that started them, then start new sessions after upgrading.

- **Use `query`, `get` and `context`.** The former `query-v2`, `get-v2` and `context-v2` names have no aliases. `query` now uses the bounded preview API: `records`, `next_cursor`, `complete` and `scan`, not the old `entries` / `next_after_seq` protocol. Remove `--after-seq`; continue with `--cursor` instead.
- **One native archive layout.** Headerless CLI v1 records, expanded schema-2 archives and legacy-import artifacts are no longer supported by CLI or GUI. Current compact native archives are supported for text, protobuf and structural records. The internal schema/profile still validates data; it is not a user-selectable product version. `--record-format` and GUI format-conversion/save variants are removed. A zero-byte file is invalid; a finalized native document with zero records is valid.
- **Transport is an acquisition choice.** Capture/start retain `--transport text|proto`, defaulting to text. There is no automatic fallback. Query reads the archive's declared representation without a `--proto` or format flag. Protobuf rows retain their original payload and derive display fields from it.
- **Restart queries after upgrading.** Current cursors use `c4` and `query.key`; old cursors, signatures and the previous key filename are not migrated. Canonical filter fingerprints and time-window anchors are checked. Existing key files and archives are left untouched. Worker configuration no longer accepts incomplete legacy fields, and the obsolete `Ciallocat` config-directory auto-import is removed.
- Use `--tag` instead of the removed `--tag-include` alias; `--tag-exclude` remains distinct. `get` rejects unused preview and scan-budget options rather than silently accepting them.

See [CLI migration](https://github.com/IllyasvielEin/Ciallogcat/blob/v1.3.0/docs/cli.md#migrating-query-callers) and the [native archive contract](https://github.com/IllyasvielEin/Ciallogcat/blob/v1.3.0/docs/native-format.md).

## Shared correctness and simpler execution

- Query, get and context enforce the same pinned byte **and sequence** upper bounds. A reference cannot escape its original snapshot even after valid source growth, and inconsistent published metadata is rejected.
- Event and unparsed rows no longer present placeholder level/PID/tag fields as real log metadata. CLI and GUI share kind-aware filters, display and full-text copy. An omitted minimum level and explicit verbose level are equivalent; meaningful metadata restrictions exclude rows without those fields.
- Final archive and decoded output enforce their respective final depth and size limits, preserve unknown extensions and exact numeric tokens, and reject inconsistent protobuf evidence. Failed atomic saves do not publish a partial destination.
- `--all` uses typed scan state instead of invoking its own paged JSON/cursor protocol. It remains a **fixed-snapshot full export**, not follow. JSONL writes validated decoded bytes directly; object key order is not a compatibility guarantee. Stored `get` preserves original archive line bytes.
- Full-model validation remains mandatory. Fixed-shape records avoid a redundant readback only when all arbitrary extension maps are empty; extension-bearing records retain final typed depth validation.

## Desktop workflows

- File-operation failures offer an editable-path retry, accessible error details and copy, without automatically retrying, overwriting an existing file or discarding the current view. A failed save-before-open does not later open an old candidate implicitly.
- Empty-state guidance, follow/browse behavior, and compact failure notices are clearer. Structural records have explicit kinds and blank non-applicable metadata in the table, accessibility text, details and copy.
- Saving and filtered export use the same native layout, with no version-conversion menu. Snapshot, cancellation, provenance and atomic-publication guarantees remain intact.

## Measurement and validation

Local final validation passed 458 default-feature tests and 309 headless tests (4 and 1 intentionally ignored), both strict Clippy configurations, formatting, 75 Python tests and pinned protobuf regeneration. Additional independent regressions covered snapshot fences, record-kind semantics, output-depth boundaries, atomic publication and exact numeric preservation. The release pipeline separately requires Linux/Windows GUI and CLI build/test/package jobs and clean Ubuntu DEB installation/removal checks before publication.

Synthetic host replay compared the final implementation with a local pre-hill-climb snapshot, not the published 1.2.2 release. Protobuf archives were about **55–62% smaller** than that snapshot's expanded layout. Full-output query CPU fell **25–56%** against its expanded/default layout and **13–47%** in like-layout comparisons. This is not a universal speedup: capture CPU versus that snapshot's compact layout was approximately **1–8% higher**, with overlapping run ranges. These are bounded synthetic replay measurements, not real-device, USB, GPU or durable-throughput results.

GUI review used actual offscreen rendered frames and interaction tests. Native desktop presentation, real Android devices, IME and long-running collection still require platform acceptance; CI and offscreen images do not establish those results.
