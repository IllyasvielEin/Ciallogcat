# GUI 文件工作流

当前源码仅支持打开原生 JSONL，无需连接设备或安装 ADB。旧 CLI v1、旧展开 schema-2、旧 legacy 导入产物与空文件不再支持；合法的零记录 native 文档仍可打开。格式契约见 [native-format.md](native-format.md)。较早发布包可能没有这些功能。

## 打开与阅读

- 使用 **File → 打开日志…** / **Ctrl+O** 输入本地路径，或将一个文件拖入窗口。当前没有系统文件选择器。
- 后台验证全部内容后才提供替换。坏行、未知必需版本、序号错误、原生文档缺少结束标记或超预算会拒绝整个候选，保留原视图。
- 有旧日志时可取消、直接替换，或“保存后打开”。后者先停止并接收旧采集的剩余数据，再保存旧文档；保存失败或取消打开均保留旧视图，此时采集已停止。
- 文件视图只读，保留筛选、详情、选择和复制。进入文件时清除旧设备的包名限制，其余阅读筛选保持。**File → 关闭文件** 关闭视图，不删除磁盘文件。选择设备会进入正常的切换确认流程。
- 导入保留 native 来源与身份，不补造缺失的观察事实；界面中的历史记录不会被当前设备的 ps 查询修改。旧文件不能通过改 schema 或补造 provenance 变成有效 native 证据。

文件操作失败时，紧凑通知优先显示错误原因，并提供 **修改路径重试…**；完整错误、保留状态和路径可悬停查看，或通过 **详情** 打开并复制（支持键盘访问）。重新使用对应的打开/另存快捷键也会恢复该路径。它只重新打开可编辑的路径对话框，不自动重试。再次确认保存时使用当前视图重新固定快照，已有文件仍不会覆盖；取消对话框保留原视图和失败路径，关闭失败通知会清除该路径。取消文件任务不提供重试入口。“保存后打开”失败会丢弃候选，后续重试仅另存当前日志，不会自动打开原候选文件。

## 保存与筛选导出

**另存保留日志…** / **Ctrl+Shift+S** 保存当前保留范围。**导出当前筛选结果…** 固定已生效的筛选表达式与源快照，后台重新筛选；不依赖正在变化的界面索引。

普通保存允许采集继续，后续新行不会进入这份快照。“保存后打开”在旧采集确认停止之后固定快照。序号保留原值，Clear、裁剪、暂停和同设备重连不从 1 重新编号；导出文件保留原会话引用和导出范围。

保存对话框显示当前保留/匹配数量及来源序号范围，实际快照在点击保存时固定。另存保留日志包含未匹配当前筛选的记录；筛选导出只保存匹配项。两者都保留采集事实、近期采集配置、主机环境及已知的设备发现信息；后续打开、筛选导出不会清除原有断流事实。详情中的 **复制引用** 明确复制 session/seq，普通 Copy 继续复制完整日志文本。

`header.view_filter` 是视图说明，内容范围以 footer 的 `scope` 为准：

- 从采集视图保存新快照时，`view_filter` 记录提交保存时已生效的阅读筛选；另存保留日志仍包含全部保留记录，`scope.filter` 不因此增加筛选条件。
- 从已打开文件**另存保留日志**（包括“保存后打开”）是源快照的复制：保留源 `view_filter`（也保留缺省状态）、原 `scope`、artifact 身份和记录的 session/seq。离线界面后来调整的阅读条件不会写入这类文件，也不会改变保存的记录范围。不再提供版本转换或兼容格式保存菜单。
- **导出当前筛选结果**产生新 artifact，将其 `view_filter` 更新为本次实际用于选取记录的冻结条件；提交后再改界面不会影响它。首次筛选时它与 `scope.filter` 相同；对已有筛选文件再次导出时，`view_filter` 仅说明本次条件，`scope.filter` 通过 `all_of` 保留此前条件与本次条件的组合，原来源范围仍保留。源采集配置、采集事实、扩展以及已打开文档与磁盘源文件保持不变。

**暂停跟随** 只停止自动滚动，仍继续采集；**暂停采集** 停止子进程并排空剩余日志。**清空视图** 只移除本机留存，不执行设备 `logcat -c`，也不清除会话观测事实。默认开始采集带最后一条设备历史后跟随，停采期间不保证回补；恢复形成的未知区间会保存到证据中。

**采集设置** 可选择最近 N 条/指定设备时间后跟随，或一次性快照。快照正常 EOF 后结束；即使静默也受 15 秒期限限制，最多 100,000 条。新增记录连同 LogStore 容器容量计入留存估算，使用当前留存预算 90% 内的剩余空间，上限 64 MiB；达到上限前停收，不靠淘汰快照前缀满足限制。预算不是 wire/file 字节或总 RSS。原有日志可能占满可用空间，此时可先保存并清空视图。显式降低留存预算仍会移除旧记录，操作前有提示。dump、tail>1、since 不套用当前 ps 的进程名称；默认短历史实时模式的 ps 名称也始终只是提示。

应用筛选旁的 **进程变化** 展示当前关注包名（含子进程）的有界 ps 观察。失败/过期采样不会被当成退出；恢复后的首次采样重新建立基线。**View → 下一条崩溃 / ANR 线索** 或 **F8** 在全部保留记录中按四类已知签名定位并打开邻近上下文，包含被筛选隐藏的记录。详情徽标可查看匹配依据，不提供根因判定。

文件始终使用同一种原生格式保存和筛选导出；protobuf 行保留一份原始 payload，文本与结构记录保留自身字段。没有用户可选的版本转换或旧格式输出。单行 8 MiB 上限和保存预算仍有效，超限失败而不截断或覆盖原文件。

目标必须是新文件。程序在同一目录创建临时文件，完整写入、flush、sync 后通过硬链接一次性发布，再移除临时名字。目标已存在、并发出现同名文件、磁盘写满或写入失败均不会覆盖它。失败/取消会尝试删除临时文件；崩溃可能遗留带 UUID 的隐藏 `.tmp` 文件。文件系统不支持硬链接时保存失败，不能据此声称所有网络盘、FAT 或移动存储都适用。此方式不承诺父目录项在断电后的持久性。

如果取消发生在发布已经完成之后，仍会如实报告文件已保存；“取消保存与打开”会取消后续视图替换，不撤回已经发布的文件。

原生文件有完成标记，但这只说明快照文件写完了。它不代表设备从未丢日志、暂停期间无缺口或筛选结果包含全部日志。CLI `query/get/context --file PATH` 使用查询 API，可读取 GUI 导出的原生文件，并保留来源的原记录身份与导出范围。

## 内存和取消边界

同一时间仅有一个文件任务。候选导入使用当前日志预算，包含候选记录、元数据和保守解析工作集；超预算整次失败，不只留下尾部。已打开的文件不能通过下调预算被静默裁剪。

该预算不是总 RSS 上限：导入时旧文档与候选同时存在，最多可各占一份预算；另有至多 8 MiB 的编码行缓冲、筛选快照、队列与图形开销。保存会固定 COW 快照，采集裁剪后它仍可暂时持有旧记录；筛选导出还会分配索引、选中记录容器与元数据。文件任务会增加峰值内存，不应把界面的 retained estimate 解释为文件操作的总内存承诺。

取消在逐行读取、快照元数据构建、筛选结果复制、完整验证、写入和发布前检查；包含原生 proto 记录的再次验证，不会先无条件验证完整文档才处理取消。普通文件 I/O、文件系统同步以及单条 JSON / protobuf 的编解码不会被强制中断。2026-10-23 的 WSLg X11 实测已完成 900×560 窗口中的路径打开、筛选、详情、保存和重开，90 条记录逐条一致，并检查 125% / 150% 缩放。原生拖放、系统 IME、Windows 文件语义和长时间真机采集仍需实际验收；单元测试和模拟 ADB 不替代这些验证。
